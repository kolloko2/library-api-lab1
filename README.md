# Library API — лабораторная работа №1

Минимальная информационная система для учёта библиотечного фонда. Проект выполняют студенты группы **241-372**: Кодзаев Николай, Парамонычева Анастасия, Палехова Мария.

## Назначение и пользователи

Система хранит авторов, книги, филиалы и физические экземпляры. Библиотекарь ведёт каталог и выдачи; читатель ищет книги и получает доступный экземпляр; администратор настраивает сервис и контролирует его состояние.

Основные сценарии: добавить автора и книгу, зарегистрировать филиал и экземпляр, найти книгу, отфильтровать доступные экземпляры, выдать экземпляр читателю и оформить возврат.

## Запуск

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
copy .env.example .env  # Linux/macOS: cp .env.example .env
uvicorn app.main:app --reload
```

После запуска: Swagger UI — `http://127.0.0.1:8000/docs`, проверка состояния — `GET http://127.0.0.1:8000/health`.

## Проверка

```bash
pytest -q
python -m compileall app
```

Подробное ТЗ, API, схема БД, Git-процесс и сценарий защиты находятся в каталоге [`docs`](docs/).

## Правила внесения изменений

1. Для изменения создаётся задача (Issue) и ветка `feature/<issue>-<name>` от актуальной `main`.
2. Коммиты должны быть небольшими и осмысленными; сообщение начинается с `feat:`, `fix:`, `docs:`, `test:` или `chore:`.
3. Перед отправкой обязательны `pytest -q` и `python -m compileall app`.
4. Изменение принимается через Pull Request после проверки кода и успешных команд проверки.
5. Запрещено коммитить `.env`, базы данных, виртуальное окружение, токены и пароли; запрещено напрямую переписывать историю `main` и выполнять force-push в неё.
6. После приёмки PR сливается в `main`; стабильная версия отмечается аннотированным тегом.

Конфигурация читается из переменных окружения. Файл `.env.example` содержит только безопасный шаблон; настоящий `.env` игнорируется Git.
