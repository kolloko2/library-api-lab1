## Локальная проверка

`make setup`, `make verify`, `make migrate`. Для Windows использовать Python из `.venv` и команды из Makefile напрямую, либо GNU Make.

## Секреты

DB_PASSWORD и GRAFANA_PASSWORD задавать локально. Пароль БД в DATABASE_URL должен быть URL-encoded. Для демонстрационного окружения допустим случайный hex-пароль. В репозиторий не загружать .env, приватные SSH-ключи, дампы и локальные БД.

## Linux без контейнеров

На Debian-сервере БД установить PostgreSQL, создать отдельные роль и БД library; ограничить pg_hba.conf адресом сервера приложения и scram-sha-256. На сервере приложения создать системного пользователя library, каталог /opt/library с кодом и venv, /var/lib/library с правами пользователя library, /etc/library/library.env с правами 0640 root:library. Установить зависимости, выполнить миграции, скопировать infra/library.service и включить `systemctl enable --now library`. Правила iptables применяет администратор из консоли с корректными ADMIN_CIDR и APP_IP; сначала проверить сохранение SSH-доступа. Сохранить правила через iptables-persistent.

## Диагностика

1. `systemctl status library` или `docker compose ps`.
2. `journalctl -u library` или `docker compose logs --tail=100 app db`.
3. `ss -lntp`, `iptables -L -n -v`, свободное место `df -h`.
4. Проверить /health и /version. Ошибка 503 указывает на проблему соединения с БД.
5. Проверить `up{job="library"}`, частоту 5xx и latency в Prometheus.
6. Вернуть предыдущий SHA через APP_IMAGE и APP_VERSION; выполнить deploy и проверку релиза. Миграции вперёд и назад требуют отдельной оценки совместимости; deploy не откатывает схему автоматически.
