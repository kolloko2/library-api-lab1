Показатели тестов относятся к итоговому коду. Отчёт ЛР3 фиксирует промежуточное состояние: девять тестов, покрытие 92,03%. Далее добавлены проверки отказа БД и отсутствия секретов в журнале.

## Команды приёмки

`make verify`: Ruff, Bandit, pytest с покрытием не менее 40%, compileall, pip-audit и проверка мутации. Контейнерные изменения: дополнительно `make container-check` на Linux с Docker Engine. Ansible: синтаксическая проверка, применение, HTTP-проверка и повторный запуск без лишних изменений.

Негативные проверки выпуска выполняет `scripts/release_negative_check.py`. Команда `scripts/incident_check.py --allow-laboratory-incident` временно останавливает лабораторную контейнерную БД, проверяет оповещение и восстанавливает БД в finally. Использовать только выделенный учебный стенд.

## Стенд и секреты

Staging: library-app 192.168.77.10 и library-db 192.168.77.11. Второе окружение: devops-clean-app 192.168.78.10 и devops-clean-db 192.168.78.11. Секреты находятся вне Git в /etc/library и защищённых переменных GitHub. Команды эксплуатации описаны в OPERATIONS.md.

Env-файлы, базы, дампы, ключи и виртуальное окружение исключены .gitignore. Синтетический тестовый секрет находится только в намеренно отклонённой ветке demo/ci-rejection.

## Правила изменений

Задача → ветка → осмысленные коммиты → Pull Request. Обязательны verify, containers и secrets; критические файлы перечислены в CODEOWNERS. Изменения правил приёмки проверяет владелец кода. Запрещены обход проверок, force-push main, удаление тестов и ослабление анализаторов ради выпуска.

На живой защите преподаватель выбирает контрольное изменение или отказ; студенты показывают диагностику и восстановление. Согласование темы и отметка преподавателя не подменяются записями в репозитории.
