## 1. Цель и назначение

Цель работы — создать минимальное приложение с HTTP API и реляционной БД, а также провести изменение по полному Git-процессу. Система автоматизирует каталог библиотеки и операции выдачи физических экземпляров.

Категории пользователей:

- библиотекарь ведёт каталог, регистрирует экземпляры, оформляет выдачу и возврат;
- читатель ищет книги и получает доступные экземпляры;
- администратор задаёт конфигурацию и проверяет состояние сервиса.

## 2. Реализованная система

Приложение написано на Python с FastAPI и SQLAlchemy. Локальная реляционная БД — SQLite. Подключение задаётся через `DATABASE_URL`, поэтому в следующих работах БД можно заменить на PostgreSQL.

Реализованы связанные сущности `Author`, `Book`, `Branch`, `BookCopy`, `Loan`. Доступны создание и просмотр справочников, поиск книг, фильтрация экземпляров, выдача и возврат. Адрес `GET /health` возвращает состояние приложения. Некорректные данные дают `422`, отсутствующие связи — `404`, нарушение уникальности или предметного правила — `409`.

Содержательное правило: выдать можно только доступный экземпляр; после выдачи он становится недоступным, после возврата — доступным. Повторная выдача и повторный возврат запрещены. Дополнительно действует настраиваемый лимит активных выдач на читателя.

## 3. Конфигурация и безопасность

Переменные окружения описаны в `.env.example`: `APP_NAME`, `APP_ENV`, `DATABASE_URL`, `MAX_ACTIVE_LOANS`. Файл `.env`, локальные базы, виртуальное окружение, кэш и файлы IDE исключены через `.gitignore`. Секретов в шаблоне нет.
